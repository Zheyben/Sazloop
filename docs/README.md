# Documentación de Sazloop

Esta carpeta es el punto de entrada para comprender el proyecto, conocer las decisiones vigentes y continuar el trabajo sin depender de explicaciones externas.

## Lectura recomendada

Si es la primera vez que trabajas en el proyecto, sigue este orden:

1. Lee [Proyecto](PROYECTO.md) para comprender el problema, la solución y el alcance.
2. Consulta el [Glosario](GLOSARIO.md) para utilizar los mismos términos que el equipo.
3. Revisa los [Flujos de negocio](FLUJOS_NEGOCIO.md) para entender cómo funciona la plataforma.
4. Lee los [Requisitos](requisitos/REQUISITOS.md) para saber qué debe hacer el sistema.
5. Consulta las [Decisiones del proyecto](decisiones/DECISIONES_PROYECTO.md) y el [Modelo de dominio](decisiones/MODELO_DOMINIO.md).
6. Revisa la [Arquitectura](ARQUITECTURA.md) antes de modificar el backend o frontend.
7. Abre el [Estado actual](tareas/ESTADO_ACTUAL.md). Los planes de semanas anteriores son históricos.

## Regla para actualizar la documentación

Cuando una decisión cambie:

1. Actualiza primero el documento oficial del tema.
2. Revisa los requisitos, flujos y modelo de dominio afectados.
3. Actualiza el estado del proyecto.
4. Después realiza los cambios en diagramas o código.

No debe mantenerse una decisión nueva únicamente en mensajes, reuniones o conversaciones.
